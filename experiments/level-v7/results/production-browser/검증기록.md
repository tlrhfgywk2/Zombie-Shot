# 탐험 프로토타입 검증 기록

## 자동 검증

- 기존 전투·탄약·부착물 테스트와 새 탐험 테스트 통과. 탐험 테스트는 시드 재현, 선택 전 목적지 확정, 도구별 정보 차이, 측량도 2회 제한, 회피 비용·교란 차단, 영구 결제·원자성·표준탄 결제 차단을 포함한다.
- 실제 `Game` 제어를 사용하는 통합 테스트에서 네 권총 × 4개 시드의 입구→전투→보상→이벤트→상인→위험 조우→탈출→재시작을 확인했다. UI와 애니메이션만 대체하며 전투 계산·재고·상태 전환은 실제 구현을 사용한다.
- 네 권총 × 40개 시드, 총 160개 기본 런의 필수 전투를 표준탄으로 완료했다. 기본 지급탄과 보상을 모두 거래해도 생존 가능한 하한을 확인한 것이며 모든 배열·위험 선택의 생존을 보장하는 검증은 아니다.
- 이벤트 4종의 선택 8가지 효과와 재실행 방지, 수동 보급 차단, 단일 상인 품목 중복 거래 방지, 보상 없는 회피, 즉사 후 탐험 재시작을 확인했다.
- TypeScript 검사·ESLint·Vite 프로덕션 빌드 통과. 기존 단일 번들의 600kB 경고는 남아 있다.
- 탄약 Excel 명세 대조 통과: 47행·51열. 기존 전투 수치와 탄약 정의는 수정하지 않았다.

## 실제 브라우저

Windows의 Edge를 Playwright로 렌더링했다. 데스크톱 **1440×900**, 세로 **390×844**에서 `browser-101` 시드의 P220 런을 각각 실제 입력과 Three.js 연출로 끝까지 진행했다. 기존 연출 속도 설정의 상한 2배를 사용했다. 브라우저 실행 오류와 탐험 카드의 가로 넘침이 없었다.

실제 화면의 제목·탄 그림·수량·버튼·컨테이너 경계를 확인했다. 세로 상인 화면은 카드 안에서 세로 스크롤로 모든 상품과 떠나기 선택에 접근한다. 메뉴·무기 선택·입구·단서·이벤트·상인·보상·위험 조우·탈출·실패·재시작을 확인했다. 프리 모드로 돌아가 M500의 초기 특수탄 지급과 수동 보급 버튼도 확인했다.

## 재현

`tools/validate-exploration.mjs`가 런 완주·경계 상태·화면 캡처를 재현한다. Vite 서버를 시작하고 Playwright가 설치된 환경에서 `node tools/validate-exploration.mjs`를 실행한다. 선택적인 환경 변수는 다음과 같다.

- `VALIDATION_BASE`: 게임 서버 주소. 기본값 `http://127.0.0.1:5173/Zombie-Shot/`.
- `PLAYWRIGHT_MODULE`: 외부 Playwright의 `index.mjs` 절대 경로. 지정하지 않으면 설치된 `playwright` 패키지를 사용한다.
- `BROWSER_CHANNEL`: 설치된 브라우저 채널. 이번 로컬 검증에서는 `msedge`를 사용했다.
