# 좀비 샷

탄창에 넣는 탄약의 **종류와 발사 순서**로 전투 결과가 달라지는 브라우저 전술 장전 게임입니다. 모바일에서도 정밀 드래그 없이 탄창을 편집할 수 있으며, 선택한 순서가 3D 장전과 사격 연출에 그대로 반영됩니다.

## 기술 구성

- Three.js
- TypeScript(엄격 모드)
- Vite
- Vitest
- ESLint

## 로컬 실행

Node.js 22 이상과 npm을 권장합니다.

```bash
npm install
npm run dev
```

Vite가 출력한 로컬 주소를 브라우저에서 열면 게임을 플레이할 수 있습니다.

## 개발 명령

```bash
npm run dev       # 개발 서버
npm run build     # 타입 검사 및 프로덕션 빌드
npm run test      # 결정론적 게임 규칙 테스트
npm run lint      # 정적 코드 검사
```

## 게임 방법

1. 하단 탄약을 눌러 1~4발을 탄창에 넣습니다.
2. 슬롯 순서가 왼쪽부터 실제 발사 순서입니다. 번호와 탄약 이름으로도 순서를 확인할 수 있습니다.
3. 탄창을 편집할 때 다음 방법을 사용할 수 있습니다.
   - 탄약 탭: 빈자리에 추가
   - 장전된 슬롯 탭 → 다른 슬롯 탭: 선택 탄환 이동
   - 장전된 슬롯 탭 → 탄약 탭: 선택 탄환 교체
   - 장전된 슬롯 탭 → `선택 탄 제거`: 선택 탄환 제거
   - 마우스·펜·터치 드래그: 탄약 삽입·교체 또는 장전된 탄환 이동
4. `탄창 장전`을 누르면 개별 탄환 삽입, 탄창 결합, 슬라이드 장전 후 자동 사격합니다.
5. 살아남은 감염체는 화상 피해를 받은 뒤 유형별 속도로 접근합니다. 충격탄은 다음 한 번의 이동을 줄입니다.
6. 웨이브 안에서는 탄약 재고가 유지되며, 다음 웨이브 진입 시 제한된 보급을 받습니다.
7. 5개 웨이브의 일반·질주·장갑·거대 감염체를 모두 막으면 검증 구간이 끝납니다.

화면 오른쪽 위의 `음향` 버튼으로 전체 소리를 끄거나 켤 수 있고, 옆 슬라이더로 전체 음량을 조절할 수 있습니다. 설정은 해당 브라우저에 저장됩니다.

탄약 수치와 적 진행 수치는 `src/data/ammoDefinitions.ts`에서 한곳에 관리합니다. 전투 계산은 Three.js 장면과 분리되어 있어 렌더러 없이 테스트할 수 있습니다.

## 탄약 순서 코어 프로토타입

전투의 중심은 권총 종류가 아니라 **어떤 탄약을 어떤 순서로 발사하는가**입니다. 각 탄환은 명중 즉시 체력·방어·상태를 갱신하며, 다음 탄환은 갱신된 상태를 기준으로 계산됩니다. 화면 프리뷰와 실제 사격은 모두 `CombatResolver`의 동일한 순차 계산 결과를 사용합니다.

- **표준탄**: 숨은 조건 없이 22 체력/방어 피해를 주는 기준 탄약
- **철갑탄**: 방어를 최대 24 먼저 파괴한 뒤 13 피해를 주는 선행 준비탄
- **확장탄**: 방어가 없으면 30 피해, 방어가 남아 있으면 12 피해
- **소이탄**: 11 직접 피해와 함께 적 행동 2회에 걸쳐 회당 7 화상 피해
- **충격탄**: 9 피해 후 다음 탄환을 1.4배로 증폭하고 다음 적 이동을 35%로 억제
- **매그넘탄**: 31 직접 피해를 주지만 시작 시 1발만 제공되는 희귀 탄약

대표적인 상호작용은 `철갑 → 확장`과 `충격 → 매그넘`입니다. 임의의 순서 보너스가 아니라 앞 탄환이 바꾼 방어/노출 상태 때문에 결과가 달라집니다. 사격은 각 탄환마다 피해와 상태 적용, 사망 확인을 마친 뒤 다음 탄환으로 넘어가며 사망 후 남은 탄환은 적용하지 않습니다.

적 상태는 체력, 방어, 거리, 화상 남은 턴, 이동 억제, 다음 탄 노출만 표시합니다. 일반 감염체는 기준 표적, 장갑 감염체는 철갑 선행 순서, 질주 감염체는 충격탄의 이동 억제, 거대 감염체는 긴 연계를 시험하도록 구성했습니다.

현재 프로토타입은 4발 탄창, 6종 탄약, 5개 결정론적 웨이브만 제공합니다. 상점·영구 성장·다중 무기·무작위 명중·보스는 의도적으로 제외했습니다. Unity 이전에는 실제 플레이로 특수탄을 아끼는 판단이 충분히 자주 생기는지, `철갑 → 확장 → 표준 → 표준`이 장갑 적 외에서도 지나치게 강하지 않은지, 충격탄의 이동 이득이 즉시 피해 희생을 정당화하는지, 10~20분 반복 플레이에서 보급량이 답답하거나 넉넉하지 않은지를 평가해야 합니다.

## 빌드와 배포

```bash
npm run build
```

결과물은 `dist/`에 생성됩니다. Vite 기본 경로가 `/Zombie-Shot/`으로 설정되어 GitHub Pages 프로젝트 하위 경로에서 동작합니다.

`.github/workflows/deploy-pages.yml`은 `develop`의 정확한 커밋을 검사하고 테스트·린트·빌드를 실행한 뒤 `dist/`를 유일한 공식 Pages 빌드로 배포합니다. CI가 주입한 소스 SHA는 화면의 `BUILD` 표식과 배포 커밋에 함께 기록됩니다. 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 한 번 설정해야 할 수 있습니다.

## 브랜치 작업 흐름

기능 및 수정 브랜치는 최신 `develop`에서 분기해 작업하고 검증 후 PR로 `develop`에 병합합니다. 일반 Codex 작업은 자신의 PR을 자동 병합하지 않으며 `release`와 `main`을 변경하지 않습니다.

```text
develop → task branch → PR checks/review → develop → GitHub Pages
```

`main`은 초기 안정 기준선으로 유지합니다.

### Cloud-first 새 작업

1. 최신 `develop`에서 Codex Cloud 작업을 시작하고 전용 task branch를 사용합니다.
2. 구현 후 `npm test`, `npm run lint`, `npm run build`를 실행하고, 시각 변경은 실제 브라우저에서 데스크톱 `1440x900`과 세로 `390x844`를 확인합니다.
3. `develop` 대상 PR을 열면 배포 없는 PR checks가 실행됩니다. 리뷰하고 필요하면 Codespaces에서 플레이테스트한 뒤 사람이 병합합니다.
4. 병합 후 Pages 배포가 끝나면 화면의 BUILD SHA가 병합된 소스 revision과 같은지 확인합니다.

### Codex 계정 간 작업 인계

Account A는 유용한 진행을 task branch에 커밋하고 PR의 `## Codex Handoff`를 현재 상태, 남은 일, 검증 결과, 중요 파일, 정확한 다음 단계로 갱신한 뒤 멈춥니다. Account B는 같은 PR을 열고 `AGENTS.md`와 handoff를 읽은 다음 PR head branch를 checkout하여 커밋과 `develop` 대비 diff를 확인하고 `Exact next step`부터 계속합니다. 이전 Codex 대화나 Windows PC는 필요하지 않습니다.

### Codespaces/태블릿 미리보기

PR head branch로 Codespace를 만든 뒤 다음을 실행합니다.

```bash
npm run dev -- --host 0.0.0.0
```

자동 전달된 **Zombie Shot Preview** 포트 5173을 태블릿 브라우저에서 엽니다. 포트는 자동으로 공개되지 않으며 필요할 때 Codespaces의 포트 설정에서 접근 범위를 선택합니다. Task branch는 공식 Pages를 배포하지 않습니다.

## 실제 휴대전화 확인 목록

- Android Chrome과 iPhone Safari에서 각각 첫 화면을 열고 첫 조작 뒤 효과음이 재생되는지 확인
- 각 브라우저의 세로·가로 방향에서 체력, 거리, 단계, 탄창, 음향 제어가 겹치거나 잘리지 않는지 확인
- 주소창을 접고 펼쳤을 때 하단 조작부와 3D 캔버스가 새 화면 높이에 맞게 조정되는지 확인
- 탄약 탭 추가, 슬롯 선택 이동, 교체, 제거와 손가락 드래그를 각각 반복 확인
- 드래그 중 페이지가 움직이거나 선택 강조가 남지 않는지 확인
- 음소거와 음량을 변경한 뒤 새로고침해 설정이 유지되는지 확인
- 연속 장전·사격을 여러 번 실행해 프레임 속도와 음향이 안정적인지 확인
- 게임 오버와 다시 시작을 반복한 뒤 탄창 편집과 사격이 계속 정상인지 확인

## 현재 한계

- 권총, 탄창, 좀비는 가벼운 절차적 저폴리 모델이며 추후 GLTF 에셋으로 교체할 수 있습니다.
- 효과음은 라이선스 의존성이 없는 Web Audio 합성이며 브라우저별 첫 상호작용·백그라운드 복귀 정책은 실기기 확인이 필요합니다.
- 적은 탄약 순서 검증에 필요한 4개 기능 프로필만 있으며, 다중 표적 동시 조준은 없습니다.
- 밸런스는 결정론적 샘플과 자동 테스트 기준의 1차 수치이며, 주관적인 재미와 실제 최적 전략은 개발자의 반복 플레이가 필요합니다.
- 일부 구형 모바일 브라우저의 Pointer Events 동작과 기기별 오디오 정책은 실제 기기 확인이 필요합니다.
- 저장, 영구 성장, 상점, 다중 무기, 웨이브 시스템은 의도적으로 포함하지 않았습니다.
