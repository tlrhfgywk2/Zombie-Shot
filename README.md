# 좀비 샷

탄약의 종류와 발사 순서, 권총 장착물 조합, 다음 조우 경로를 함께 설계하는 브라우저 전술 장전 게임입니다. 선택한 탄환 순서는 3D 장전·사격 연출과 동일하게 처리되며, 데스크톱과 세로형 모바일 화면을 모두 지원합니다.

## 기술 구성

- Three.js
- TypeScript 엄격 모드
- Vite
- Vitest
- ESLint

## 로컬 실행

Node.js 22 이상과 npm을 권장합니다.

```bash
npm install
npm run dev
```

Vite가 출력한 로컬 주소를 브라우저에서 열면 게임을 플레이할 수 있습니다.

## 개발 명령

```bash
npm run dev           # 개발 서버
npm run test          # 결정론적 규칙·회귀 테스트
npm run test:balance  # 168개 조우 + 384개 전체 경로 밸런스 보고서
npm test -- src/simulation/SequenceAudit.test.ts # 순서·거리 수치 감사
npm run lint          # 정적 코드 검사
npm run build         # 타입 검사 및 프로덕션 빌드
```

## 게임 방법

1. 가상 서비스 권총 `서비스 .45`와 빈 부착물 보관함으로 시작합니다. 특수 감염체를 처치하면 미소유 부착물 1개를 받고, 총구·탄창·조준 장치·전술 레일·손잡이 슬롯에 장착할 수 있습니다.
2. 표준탄 ∞, 확장탄 3발, 철갑탄 3발로 시작합니다. 탄약을 눌러 탄창 최대 용량(기본 4발, 확장 시 5·6발) 안에서 탄창에 예약합니다. 실제 발사한 특수탄만 스테이지 잔량에서 빠집니다.
3. 한 발만 장전해도 발사할 수 있습니다. 장전된 탄약은 탄창 슬롯을 누르면 즉시 제거되며, 순서 이동과 탄약 교체는 마우스·펜·터치 드래그로 조작합니다.
4. 화력, 장갑, 충격, 다음 행동 임계치와 인접 탄약의 예상 효과를 확인한 뒤 `탄창 장전`을 누릅니다.
5. 살아남은 감염체는 접근·특수 행동·치명 공격 중 하나만 수행합니다. 충격은 턴 사이에 남으며 임계치만큼 소비해 행동을 중단합니다. 접근 도착 후에도 다음 장전 턴이 주어집니다. 같은 구간의 적 사이에는 탄약을 회복하지 않습니다.
6. 구간 완료 후 일반·고급 탄약 3종 중 하나를 골라 런 배분을 늘립니다. 특수 용량 14발이 가득 찼으면 기존 배분 1발을 직접 교체합니다. 다음 경로에 진입할 때 새 배분만큼 잔량을 회복합니다.
7. 다섯 단계를 버티면 검증 구간이 끝납니다.

화면 오른쪽 위의 `음향` 버튼과 슬라이더로 소리를 조절할 수 있으며 설정은 브라우저에 저장됩니다.

## 핵심 빌드 시스템

- 서비스 .45의 무기 화력 항은 0이며 작은 탄약 화력이 직접 사격의 기준입니다. 무기·탄약·장착물·상태 화력을 합산한 뒤 거리 손실을 한 번 적용하고, 양수 화력을 최근접 정수로 반올림하되 정확히 `.5`면 올립니다. 유효 사격의 최종 화력은 최소 1입니다.
- 충격은 자동 감소 없이 유지되는 행동 제어 자원입니다. 충분하면 다음 행동의 임계치만 소비해 그 행동을 중단합니다.
- 강한 반동은 바로 다음 탄의 화력 -2, 안정탄은 이를 흡수, 충격 포화는 바로 다음 탄의 충격 -2입니다. 두 순서 효과는 탄창 끝에서 사라집니다. 사격 때문에 적이 접근하지 않습니다.
- 권총 사거리는 근거리·중거리·원거리 세 단계이며 서비스 .45의 화력 손실은 각각 0%·10%·25%입니다. 거리 특화 탄약과 조준 장치는 고정 퍼센트포인트만 완화합니다.
- 방어 파괴를 먼저 적용한 뒤 남은 방어가 피해를 흡수하며 소모됩니다. 단, 방어 파괴 탄은 같은 한 발의 피해 흡수로 방어도를 중복 소모하지 않습니다. 초과 방어 파괴는 체력 피해가 되지 않습니다. 별도 관통 능력치는 없습니다.
- 활성 탄약은 일반 5종·고급 4종입니다. 화력·방어 파괴·충격·순서 특성과 거리 손실 완화를 표시하며 원소·신화 탄약은 현재 진행에서 제외합니다.
- 장착물은 한 슬롯에 하나만 장착합니다. 탄창 용량과 조준기의 거리 손실 완화를 유지하며 기존 반동 감소 장착물은 총기 흔들림 연출만 줄입니다. 보상은 일반 70%·고급 30%이며 같은 런에서 중복을 피합니다.
- 오염 투척체, 지반 파쇄체, 공명 비명체는 각각 장착물 슬롯, 강한 반동 후속 화력, 유효 사거리를 압박하며 행동을 미리 예고합니다.

부착물 확정 수치와 검증 내용은 [서비스 .45 부착물 문서](docs/SERVICE45_ATTACHMENTS.md)에 정리했습니다.

전투 계산과 밸런스 결정의 상세 근거는 [빌드 시스템 설계 문서](docs/BUILD_SYSTEMS.md)를 참고하세요.

충격·순서 규칙과 밸런스 한계는 [개편 기록](docs/ACTION_SHOCK_REWORK.md)에 정리했습니다. [이전 반동·거리 기록](docs/RECOIL_DISTANCE_REWORK.md)은 역사 문서로 보존합니다.

## 빌드와 배포

```bash
npm run build
```

결과물은 `dist/`에 생성됩니다. Vite 기본 경로는 `/Zombie-Shot/`이며 GitHub Pages 프로젝트 하위 경로에서 동작합니다.

`.github/workflows/deploy-pages.yml`은 `develop`의 정확한 커밋을 검사하고 테스트·린트·빌드를 실행한 뒤 `dist/`를 공식 Pages 빌드로 배포합니다. CI가 주입한 소스 SHA는 화면의 `BUILD` 표식과 배포 커밋에 함께 기록됩니다.

## 브랜치 작업 흐름

기능 및 수정 브랜치는 최신 `develop`에서 분기해 작업하고 검증 후 PR로 `develop`에 병합합니다. `develop` 대상 PR은 필수 검사가 모두 통과하고 병합 가능한 상태이면 Codex 에이전트가 사용자 확인을 기다리지 않고 직접 병합한 뒤 Pages 배포 성공까지 확인합니다. 따라서 일반적인 개발 작업은 에이전트 완료 보고 후 바로 배포된 게임을 플레이할 수 있는 상태를 목표로 합니다. `release`와 `main`은 자동 병합하지 않으며 일반 기능 개발에서 변경하지 않습니다.

```text
develop → task branch → PR checks → agent merge → develop → GitHub Pages
```

계정 간 인계 시에는 task branch의 커밋과 PR의 `## Codex Handoff`를 기준으로 이어서 작업합니다. 대화 기록이나 원래 개발 PC가 없어도 현재 상태, 검증 결과, 남은 일을 복구할 수 있어야 합니다.

## 화면 검증 기준

- 데스크톱: 1440×900
- Galaxy S23+ 비율의 세로 화면: 390×844
- 작업대, 탄약 재고, 탄창, 충격·순서 프리뷰, 다음 적 행동, 경로 선택이 전투 장면을 가리지 않는지 확인
- 실제 휴대전화에서는 브라우저 주소창 변화, 터치 드래그, 오디오 재개 정책을 추가 확인

## 현재 한계

- 권총, 장착물, 좀비는 가벼운 절차적 저폴리 모델입니다.
- 현재 플레이 가능한 총기군은 권총 하나지만 전투 계산과 장착물 소켓은 향후 총기군 확장을 막지 않도록 분리돼 있습니다.
- 저장, 영구 성장, 상점, 무작위 명중, 다중 표적 동시 조준은 포함하지 않았습니다.
- 자동 시뮬레이션은 상대 비교와 회귀 탐지용입니다. 실제 재미와 장기 최적 전략은 반복 플레이 및 실기기 검증이 필요합니다.
