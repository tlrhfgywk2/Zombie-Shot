# 탄약 계층과 명세 관리

최신 정성 설계는 [탄약 설계](탄약_설계.md), 구현 수치의 읽기용 명세는 [탄약 Excel](ZombieShot_Ammo_Spec.xlsx)이다. 수치는 `src/data/ammoDefinitions.ts`에서 변경하고 Excel을 재생성한다. 확정 탄약 46종 중 34종은 기존 구현을 유지했다. 복사탄, 교차탄, 매개탄, 잔향탄과 배열탄 8종을 추가했다. 넉백탄(?)은 미정 숫자를 빈칸으로 둔 초안이며 활성 정의·보급·보상·장전에서 제외한다.

## 계열과 계층

`family`는 체력·폭발·화상·상처·충격의 다섯 적 효과 계열이다. `category`는 직접 효과·탄약 연계·탄창 배열의 기계적 분류, `layers`는 적·탄약·탄창 계층의 조합이다. 계열을 복사한 효과에 따라 바꾸지 않는다. 복사탄은 상처를 복사해도 체력 계열, 중량탄은 체력 피해도 주지만 충격 계열이다.

규칙의 조건과 작용은 `AmmoRule`에 선언하고 `AmmoRules.ts`에서 공통으로 해결한다. 직전·다음 계열, 이웃 계열, 첫·끝·중간 칸, 계열 다양성, 단일 계열, 빈 칸, 대칭 칸 조건을 재사용한다. 작용은 현재 또는 다음 탄의 특정 수치/주효과에 정수 추가·비율 증가, 직전 주효과 복사·부분 재발동이다. 특수 탄약 ID를 나열하는 전투 분기는 추가하지 않았다.

기존 연계탄의 다음 화력 +4, 연소촉진탄의 다음 화상 +50%, 연쇄충격탄의 다음 충격 +3을 공통 규칙으로 이관했다. 인체공학 손잡이는 기존처럼 정수 후속 강화에 +1을 더한다. 다음 강화는 바로 다음 한 발에서 소비되고 전달 규칙의 수치를 다시 키우지 않는다.

## 주효과와 해결 순서

`primaryEffects`가 복사·주효과 증폭 대상을 명시한다. 체력 계열은 화력, 폭발·화상·상처·충격은 해당 축적 값이며 발화탄은 화력이다. 중량탄은 화력+충격을 의도적으로 함께 복사한다. 기존 무기 특성의 단일 강화 대상 `primaryPayload`는 그대로 유지하므로 M1911/M500의 중량탄 강화는 기존처럼 충격만 조정한다.

무기 조정·특성, 현재 적 상태에 따른 탄약 조건, 자기 배열 효과와 직전 탄의 전달 효과를 계산한 값에서 주효과만 저장한다. 취약 배율·거리·반동·외부 충격 부착물 보정은 이 저장 값에 포함하지 않는다. 복사된 화력도 현재 탄의 거리·반동·취약으로 해결된다. 복사탄은 자체 무기 화력 조정·특성을 다시 더하지 않으며 첫 발에서는 효과가 없다. 잔향탄은 자체 화력과 각 주효과의 50%를 버림하여 합친다.

이전 숫자 벡터만 복제하고 이전 규칙을 실행하지 않는다. 이동, 반동, 즉시 화상 피해, 취약 발동 추가 피해·지속·상처 보존, 다음 탄 전달, 배열 검사는 복제하지 않는다. 연속 복사는 같은 값이며 고압탄→잔향탄 반복의 기본 주화력은 8→5→3→2→2→2이다. 증폭은 현재 주효과에만 적용되며 재귀 호출이 없다.

상처는 계속 임계치 6의 축적 상태다. 임계치 소비 후 초과분을 남기고 취약 기본 2턴을 부여한다. 새 취약은 후속 탄부터 체력 화력 +50%를 적용한다. 충격은 현재 명중에서 폭발을 기폭하고 적 행동 단계에서 행동 임계치만 소비한다. 기존 폭발·점화·이동·반동·거리 규칙을 유지한다.

## 확정 탄창

`Magazine.commit()`은 장전 순서·각 탄의 계열·실제 사용 가능 용량·계열 수·빈 칸을 복제해 동결한다. 일반 탄창은 발사를 시작할 때, M500은 순서 유지/실린더 회전 결정 후 발사할 때 확정한다. 전투 해결 전체가 같은 스냅샷을 사용하므로 `Player.fireRound()`의 첫 탄 제거는 배열 조건에 영향을 주지 않는다.

첫·끝은 용량의 양끝이 아니라 장전된 순서의 첫·끝이다. 한 발은 첫 칸이자 끝 칸이며 중앙탄은 비활성이다. 이웃은 원래 장전 이웃을 사용한다. 대칭은 `장전 수 - 1 - 현재 0기준 인덱스`이며 빈 칸과 홀수 중앙의 자기 자신은 제외한다. 단일 계열은 부분 장전·한 발에서도 가능하고 다양성은 자신을 포함한 선언 계열을 중복 없이 센다. 빈 칸은 실제 용량에서 장전 수를 뺀다. 부착물 봉쇄가 줄인 용량을 사용한다.

탄약 계층의 직전 탄은 실제 직전 발사 탄이다. 다음 탄은 확정 순서의 다음 발이다. 새 전투 해결마다 전달 효과·복사 값·반동을 초기화하므로 재장전·새 턴·새 표적·재시작으로 이월하지 않는다.

## 신규 수치

| 탄약 | 기본 화력 | 반동 | 추가 조건 효과 |
|---|---:|---:|---|
| 복사탄 | 0 | 1 | 직전 주효과 100% 복사 |
| 교차탄 | 2 | 1 | 직전과 다른 계열이면 화력 +4 |
| 매개탄 | 1 | 0 | 직전·다음 계열이 다르면 다음 주효과 +50%, 버림 |
| 잔향탄 | 1 | 0 | 직전 주효과 50% 재발동, 버림 |
| 초탄 | 3 | 1 | 첫 장전 칸에서 +3 |
| 종결탄 | 3 | 1 | 마지막 장전 칸에서 +4 |
| 중심탄 | 4 | 1 | 양 끝이 아닌 칸에서 +2 |
| 교차배열탄 | 3 | 1 | 원래 양옆 탄이 다른 계열이면 +4 |
| 혼합탄 | 3 | 1 | 장전 계열 수 −1만큼 추가, 최대 +4 |
| 집중탄 | 2 | 1 | 모든 장전 탄이 체력 계열이면 +4 |
| 경량장전탄 | 4 | 0 | 빈 칸마다 +2 |
| 대칭탄 | 3 | 1 | 반대편 장전 탄이 같은 계열이면 +3 |

기존 34종의 수치를 유지했다. 집중탄은 초기 기본 화력 3에서 2로 조정했다. 초기 집중 연사 28 피해는 고압 연사 25 피해를 넘어 조건의 비용에 비해 강했다. 최종 P220 근거리 집중 연사는 24 피해, 초탄·집중·중심·종결은 25 피해다. 혼합탄은 다섯 계열에 도달해야 화력 7이며 혼합 배열의 적 상태 준비를 보상한다.

경량장전은 4칸에 한 발 화력 10, 6칸에 한 발 14다. 6칸에 경량 4발을 쓰면 32 피해로, 빈 두 칸·특수탄 4발·상태 효과 부재를 지불하는 전략이다. 장기 보급에서 경량장전 반복과 고출력 탄의 복사 조합은 추가 관찰이 필요하다.

## UI

보급·보유·툴팁의 설명을 같은 정의에서 생성한다. 기존 탄의 체력 조건·이동·회복도 수치와 함께 표시한다. 툴팁은 계열과 연계/배열 분류를 분리하고 증가 대상·수치·조건을 설명한다. 슬롯의 채운 마름모는 활성, 빈 마름모는 미활성이며 자세한 조건은 툴팁으로 확인한다. 표시는 적의 전체 피해 결과를 새로 예측하는 기능을 추가하지 않는다. 기존 결과 예상은 유지한다.

## Excel 생성과 불일치 검사

`Ammo_Master`, `Definitions`, `Balance_Notes`, `Validation`의 네 시트를 생성한다. 47행·51열이며 기본/조건 수치를 숫자 열로 분리한다. 확정 탄의 해당 없음은 0, 초안 미정은 빈칸이다. 첫 행 및 탄약 ID·한국어 이름 두 열을 고정하고 전체 표에 필터를 제공한다. 짧은 툴팁은 게임 설명 함수에서 생성한다.

Excel 작성은 개발 도구 `@oai/artifact-tool`만 사용하며 게임 실행 의존성을 추가하지 않는다. Vite의 기존 개발 로더로 정규 TypeScript 데이터를 읽는다. 도구가 기본 경로에 없으면 `--artifact-modules`에 해당 `node_modules` 경로를 전달한다.

```powershell
npm run export:ammo -- --artifact-modules "<Excel 작성 도구의 node_modules 경로>"
npm run check:ammo-spec
```

`--preview <폴더>`로 검토용 이미지도 생성할 수 있다. 생성 직후 파일을 다시 읽어 모든 셀을 정규 데이터와 대조한다. 별도의 검사기는 Python 표준 라이브러리만 사용하며 Excel 셀·고정·필터·시트를 검사한다. PR와 develop 배포 워크플로에서 이 검사를 실행한다. 따라서 정의나 UI 설명을 변경하고 명세를 갱신하지 않으면 검사가 실패한다. Excel 자체를 편집해도 게임 수치는 바뀌지 않는다.

이 환경의 npm 실행 파일은 제공되지 않아 같은 스크립트를 번들 Node 실행 파일과 각 패키지 진입점으로 실행했다. Python 경로를 지정해야 할 때는 `node tools/check-ammo-spec.mjs --python "<Python 실행 파일>"`을 사용한다.

## 검증

`AmmoLayers.test.ts`는 조건·주효과·스냅샷·복사 재귀 방지·획득/장전/사격/초기화를 검증한다. 기존 전투 테스트도 전체 실행한다. `AmmoLayerBalance.test.ts`는 대표 12개 탄창의 세 거리와 실제 적 7종을 비교한다. 브라우저 검증과 정확한 배포 결과는 [검증 기록](validation/ammo-layers/검증기록.md)에 남긴다.
