# 권총 시스템 검증 기록

검증일: 2026-10-01. 로컬 화면은 `BUILD LOCAL`이며 배포 리비전과 Pages 결과는 이 변경의 GitHub PR에 기록한다.

## 실린더 장전 잠금 후속 수정

M500은 장전이 끝나면 탄약 배열을 수정하거나 준비 단계로 돌아갈 수 없다. 유지·회전 선택은 한 번뿐이며, 선택 뒤에는 발사만 가능하다. 이전 구현의 장전 수정 버튼·콜백·상태 복귀 경로를 제거했다. 아래 초기 검증 화면에 남아 있는 장전 수정 버튼은 수정 전의 기록이다.

- 회귀 테스트에서 실린더 선택→준비·재장전 전환이 거부되고, 실제 발사→적 행동 뒤에만 다음 탄창을 준비할 수 있음을 확인했다. 전체 193개 테스트·ESLint·TypeScript·프로덕션 빌드 통과.
- 1440×900에서 한 발 장전의 회전 비활성, 슬롯 클릭으로 탄이 제거되지 않는 상태, 유지 선택 뒤 발사만 남는 상태를 확인했다.
- 4발 장전의 선택 전 및 회전 결과를 1440×900·390×844로 렌더링 확인했다. 결과에서 모든 탄약 슬롯이 수정 불가이며 재회전·수정 버튼이 없었다. 실제 발사 뒤 다음 탄창의 준비가 다시 가능했다.
- 화면: [한 발 선택](m500-locked-one-round-desktop.jpg), [순서 유지](m500-locked-keep-desktop.jpg), [4발 선택](m500-locked-choice-desktop.jpg), [회전 결과 데스크톱](m500-locked-spin-desktop.jpg), [회전 결과 세로](m500-locked-spin-portrait.jpg).

## 자동 검증

- 전체 테스트: 21개 파일, 193개 테스트 통과.
- ESLint 통과, TypeScript `tsc -b` 통과, Vite 프로덕션 빌드 통과.
- 이 Windows 환경에는 `npm` 실행 파일이 없어 각 npm 스크립트가 호출하는 저장소 도구를 Node로 직접 실행했다. GitHub PR 검사는 `npm ci`, `npm test`, `npm run lint`, `npm run build`로 재검증한다.
- Three.js를 포함한 기존 단일 번들에는 600kB 크기 경고가 남는다. 빌드는 성공했다.
- 탄약 전수 매핑, 네 계열의 연속 보너스·첫 탄 증폭, 계열 변경·새 탄창 초기화, 지연 반동의 회복·소비, 부착물 봉쇄, M500 확장 탄창 제외, 회전 시작 후보와 순서·재고, 미발사 탄 재고 보존, 미리보기 일치를 검사했다.

## 결정론적 밸런스

- 기본 탄창: 네 권총 × 10개 탄창 × 세 거리 = 120개 비교.
- 회전: M500의 모든 가능한 다른 시작 칸을 열거하고 평균·최고·최저를 기록했다.
- 부착물: 확장 탄창, 손잡이, 제퇴기, 보정기, 보정기+손잡이, 연장 총열+권총 조준경.
- 적 행동 포함: 일반·거대·고속 표적 × 세 거리 × 10개 탄창 × 네 권총 = 360개 조우.
- 결과와 후보 변경 이유는 [권총 문서](../../PISTOL_WEAPONS.md), 수치 원자료는 같은 폴더의 CSV 세 파일을 참조한다.

## 실제 전투

실제 게임의 선택·장전·발사를 브라우저에서 조작했다. 계산기를 호출해 상태를 주입하는 방법으로 전투를 대체하지 않았다.

| 무기와 탄창 | 발사 전 미리보기 | 실제 결과 |
|---|---|---|
| P220, 표준탄 4발, 8m | 피해 18, 반동 0 | 체력 22→4, 이후 적 접근으로 6m |
| M1911, 표준탄 5발, 8m | 피해 22, 연속 보너스 0/1/1/1/1 | 처치 후 표적 2/2 등장 |
| 데저트 이글, 표준탄 4발, 8m | 피해 20, 저장 반동 4 | 체력 22→2, 이후 6m |
| M500, 표준탄 1발 순서 유지, 8m | 피해 6 | 체력 22→16, 이후 6m |
| M500, 표준탄→열상탄→절개탄→열상탄 회전, 6m | 절개탄→열상탄→표준탄→열상탄, 피해 14, 상처 5 | 체력 16→2, 상처 5, 열상탄 재고 3→1·절개탄 3→2 |
| M500, 같은 원본 탄창 회전, 8m | 열상탄→표준탄→열상탄→절개탄, 피해 18, 상처 3 | 체력 22→4, 상처 3, 이후 6m |

M500의 한 발 장전에서는 회전 버튼이 비활성화됐다. 순서 유지·회전 어느 선택도 즉시 발사하지 않았고, 결과를 확인한 뒤 별도 발사 버튼을 눌렀다. 상처 주효과 3→5와 체력 주효과의 보너스 +4를 각각 확인했다. 원형 순서와 실제 탄약 소모가 미리보기와 일치했다. 실행 중 브라우저 오류 로그는 없었다.

## 렌더링 검증

데스크톱 1440×900과 세로 390×844의 CSS 뷰포트에서 확인했다. 브라우저 캡처 도구는 세로 화면의 마지막 1px을 제외한 390×843 이미지를 반환한다.

- 권총 선택, 4발·5발·6발 탄창, 빈 탄창의 장전 비활성 상태.
- 긴 이름, 상처·폭발·충격·반동·이동 수치 조합, 처치 예상으로 뒤쪽 탄이 미발사되는 상태.
- 탄 그림·제목·핵심 수치의 기준선과 컨테이너 경계를 실제 캡처로 확인했다. 6발 긴 이름의 이동 수치가 잘리는 문제를 발견해 슬롯 높이와 제목·보너스 공간을 정리한 뒤 재검증했다.
- 경계 상태는 개발 전용 임시 페이지에서 실제 GameUI와 CombatResolver로 구성했다. 임시 페이지는 최종 소스에 포함하지 않는다. 실제 전투와 3D 모델은 위의 정상 게임에서 확인했다.
- 네 무기 모두 기존 P220 모델을 공유하며 손·팔 모델과 일반 플레이용 진단 표시는 추가하지 않았다.
