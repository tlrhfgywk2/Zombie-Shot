# 탄약 계층 검증 기록

2026-10-06 한국 시간, `codex/ammo-magazine-layers`에서 검증했다. 설계는 사용자 제공 `탄약 정리.md`의 사본 `docs/탄약_설계.md`를 기준으로 삼았다. 해당 문서에 신규 계층 항목이 모두 포함되어 있다.

## 자동 검사

- Vitest: 27개 파일, 429개 테스트 통과. 기존 전투·권총·상처·화상·폭발·충격 검사 포함.
- TypeScript: `tsc -b` 통과.
- ESLint: 오류·경고 없이 통과. 저장소에서 무시하는 로컬 검증 도구 폴더는 정적 분석 대상에서 제외했다.
- Vite: 프로덕션 빌드 통과. 기존 develop `249405a`의 JS 681.15 kB와 최종 변경의 692.61 kB 모두 같은 600 kB 번들 경고를 출력했다. 이번 작업에서 새 종류의 빌드 경고를 추가하지 않았다.
- Excel: 47행·51열의 모든 셀을 구현 데이터와 대조했다. 첫 행·두 이름 열 고정, 필터 범위 및 네 시트 구성을 확인했다. Validation 시트의 12개 차이 값은 모두 0이다.
- 표 렌더링: 기본 수치·용어·밸런스·검증 시트 이미지를 확인했다. 숫자 열은 숫자, 조건과 설명은 줄바꿈으로 표시된다.

로컬 환경에 npm 실행 파일이 없어 번들 Node로 Vitest·TypeScript·ESLint·Vite 및 개발 스크립트의 진입점을 직접 실행했다. CI는 정상 npm 스크립트를 실행한다. Python 대조기는 표준 라이브러리만 사용한다.

`AmmoLayers.test.ts`는 전·후 탄 조건, 빠진 이웃, 신규 12종, 주효과 다섯 축과 중량탄 복합 효과, 무기 특성 중복 방지, 복사 재귀 방지, 고정 배열, 대칭·한 발·부분 장전·무기별 4~6칸 용량·부착물 봉쇄·보상 획득·재장전/새 턴/초기화를 검증한다.

`AmmoLayerBalance.test.ts`는 대표 탄창 12개를 거리 3/7/11m에서 비교하고 실제 적 7종의 체력·행동으로 해결한다. P220 근거리 결과는 표준 4발 20, 고압 4발 25, 집중 4발 24, 단일 배열 25, 다섯 계열 5발 21, 교차 계열 17, 초탄·연계·중심·종결 25, 초탄·절개·매개·종결 19, 부분 경량·종결 15, 6칸 경량 4발 32, 고압·복사·잔향·복사 25다. 장기 보급에서 모든 가능한 조합의 최적화를 검증한 것은 아니다.

## 실제 브라우저 사격

게임의 일반 보급·장전·드래그·사격 UI를 사용했다. P220 훈련 표적을 유지하면서 적 행동에 따른 거리와 약화 상태도 그대로 적용했다. 아래 피해는 장전 전 예상값과 사격 후 체력 차이가 일치했다.

| 순서 | 탄창 | 사격 시 상태 | 확인 결과 |
|---|---|---|---|
| 1 | 초탄·집중·중심·종결 | 12m | 20 피해, 배열 네 조건 활성 |
| 2 | 절개·교차·폭발·교차 | 12m, 반동 교란 +1 | 11 피해, 상처 3·폭발 2 잔량 |
| 3 | 경량장전·종결 | 12m, 반동 교란 +1 | 12 피해, 빈 두 칸 보상, 사격 후 교란 만료 |
| 4 | 초탄·연계·중심·종결 | 10m | 20 피해, 다음 화력 전달과 끝 칸 보상 |
| 5 | 초탄·절개·매개·종결 | 10m, 거리 교란 | 20 피해, 상처 6 도달로 취약 발동, 다음 탄 주효과 50% 증가 |
| 6 | 고압·복사·잔향·복사 | 8m, 취약 1턴·거리 교란 | 30 피해, 새 턴 이전 전달 없이 복사 연쇄 |
| 7 | 절개·소이·폭발·평두·혼합·교차배열 | 8m, 대용량 탄창 | 23 피해, 상처 3·화상 8·충격 4, 기존 폭발까지 기폭 후 잔량 0 |

단일 배열의 초탄을 끝으로 옮기면 초탄·종결이 빈 마름모로 바뀌고 예상 피해가 20에서 14로 줄었다. 실제 드래그로 첫 칸에 복원하면 두 조건이 다시 활성화되었다. 매개탄은 다음 탄이 없을 때 미활성이며 종결탄을 추가하자 활성으로 바뀌었다.

## 화면 경계

데스크톱 1440×900, 세로 390×844에서 실제 렌더링을 확인했다. 빈 탄창, 채운 6칸, 긴 한국어 이름, 복사된 상처+반동 조합, 배열 활성/미활성, 잔향 툴팁, 조기 처치로 뒤 다섯 칸 미발사 상태에서 탄 그림·제목·수치·마름모·컨테이너를 확인했다. 마름모는 제목과 겹치지 않도록 하단으로 이동했다. 세로 화면의 슬롯 제목은 기존 짧은 이름을 사용하고 전체 이름은 툴팁에 표시한다.

높은 체력/체력 1 경계 상태는 배포·버전 관리에서 제외되는 로컬 HTML 검증 fixture로 실제 Game/UI를 시작했다. 사격은 동일한 게임 UI와 Three.js 애니메이션으로 수행했다. 체력 1에서 초탄만 소모되고 나머지 다섯 특수탄은 각각 1발 그대로 남았다. 이는 테스트용 상태 설정이며 일반 플레이에 새로운 디버그 옵션을 추가하지 않는다. 최종 검증 탭의 콘솔 오류·경고는 없었다.
